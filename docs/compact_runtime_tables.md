# 紧凑运行资源与安装端还原

此流程只改变发行存储形式。还原后的`mainlexicon.coral`与`languagemodel.coral`须与输入逐字节相同；词条编号、别名顺序、单精度词频分值、双精度一元／二元／回退参数及词元映射均不得重算或量化。

## 构建与使用

先构建`coral_table_restore`。打包时传`tools/release/package_windows.py --precompiled-tables-dir <配套目录>`，默认使用紧凑编码。也可预先运行：

```powershell
python tools/data/compact_tables.py --tables-dir <配套目录> --output <新目录>/surface_tables.cstpack.xz
coral_table_restore.exe <紧凑包> <还原目录>
```

独立还原默认拒绝覆盖。安装器显式传`--replace`：先完整解码、校验和写入同目录新暂存区，再备份旧的两个固定资源文件并发布新文件；可捕获的发布失败会恢复备份。回滚失败时保留备份位置并返回失败，不声称提供跨两文件的断电原子性。所有目录参数采用Windows宽字符路径，不依赖Python或联网。

打包工具执行相同原生还原器，核对原始两文件摘要并再次原生加载模型。安装器在还原错误时停止，不继续启动输入法；成功后删除紧凑包和还原器。原CSV发行路径保持兼容，不用于生成新模型。

## CSTPACK1格式

外层为单个XZ流，LZMA2字典64MiB，CRC64。原生端拒绝尾部数据、拼接流、不支持的校验和损坏流；解码总长度和还原两文件合计各不超过1GiB。

解压后采用显式小端编码。144字节头布局为`<8sII4Q32s32s32s>`：magic=`CSTPACK1`，version=1，flags=3，原词库长度、原模型长度、词库编码段长度、模型编码段长度，原词库SHA-256、原模型SHA-256、两个编码段拼接的SHA-256。未知版本、标志、长度或摘要不一致即拒绝。

词库段保存原64字节KNAPRGB1 v2头，随后为词条原型数和唯一字符串数（各u32）。字符串按字节序排序，以规范ULEB128前缀长度、后缀长度和后缀字节编码。原型按`(词面,读音,ID,权重位型,回退位型,标志)`排序、完全相同的记录仅保存一次；每个原型是6个u32，分别为词面引用、读音引用、ID、float32权重位型、float32回退位型、原标志。词面引用与ID列采用模2^32差分，各列再按低位至高位字节平面保存。

检索键按原字节序保存前缀长度、后缀长度、后缀和候选数（整数均为规范ULEB128）。最后是原候选顺序的原型引用，按u32四字节平面保存。原键前八字节前缀、字符串池偏移、候选区偏移及64字节对齐零填充在安装时确定性重建。编码端只接受这种规范词库布局，不对不认识的布局静默转换。

模型段保存原128字节CSLM0001头。将所有词元初始／低阶／回退分值及二元分值的完整float64位型取并集，按u64位型排序；保存u32位型数及模2^64差分后的8个字节平面。+0与-0是不同位型。词元记录为5个u32（3个概率位型引用、出弧起点、出弧数），出弧起点差分；弧记录为2个u32（目标、概率位型引用），目标差分。映射记录仍为3个u32（词条ID、序列起点、长度），前两列差分；序列保存u32词元ID。所有记录按字段、字段内从低位到高位的字节平面排列。恢复时只复制原位型，不调用浮点数学运算。

还原端额外核对模型内部正文摘要及其词库绑定。长度、引用、排序、varint溢出、非有限概率位型和输出路径类型均独立检查；错误包不能替换现有资源。人工夹具覆盖不同别名分值、浮点末位、负零、Unicode目录、损坏／截断／拼接输入、覆盖拒绝以及第二文件被占用时的备份回滚。完整用户数据留在仓库外，公开回归只使用人工夹具。
