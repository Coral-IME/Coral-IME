这是一次中等偏大的平台移植，不能通过增加一个编译目标完成。可复用现有拼音、词典和会话工作的基础，但需要新建 iOS 键盘界面，并改造引擎依赖、资源路径、配置与生命周期。

## 3. 第一版范围

M1 以 iPhone 为目标，最低系统版本在核对设备和工具链后确定。

- 容器 App：启用教程、演示状态说明、测试输入框。
- 系统键盘扩展：26 键全拼、拼音预编辑栏、候选选择与翻页。
- 基础按键：空格、回车、删除及长按连续删除。
- 中英文切换、英文大小写、数字和常用符号。
- 系统键盘切换入口，横竖屏与深浅色基本适配。
- 完全离线运行，不要求开启“允许完全访问”。

M1 使用人工编写的公开小词库验证操作链路，App 与键盘均明确标注“演示词库”。它不代表完整拼音覆盖、纠错、组句或正式输入质量，不能以演示通过代替 M2 验收。

M2 接入完整核心后，优先补齐全拼候选、常用词句、必要的纠错与基础本地学习。双拼、九宫格、滑行输入、云同步、翻译、语音、剪贴板历史、皮肤市场和神经网络重排不列入首轮交付范围。桌面端已有功能按手机需求逐项移植。

## 4. 实现方案

采用“容器 App + Keyboard Extension + C++ 静态核心”。

键盘界面先使用 UIKit，入口为 `UIInputViewController`。Swift 经 Objective-C++ 桥接调用会话，桥接层不向 Swift 暴露 C++ 对象。通过 `textDocumentProxy` 提交文本、删除文字；拼音预编辑先放在键盘内部，确认后才提交，避免用反复删除宿主文本的方式模拟组合输入。

每个扩展控制器明确持有会话和资源。切换输入目标、停用键盘及资源重建时清理预编辑；候选动作携带候选标识与快照版本，过期动作不提交。后台加载或查询如有必要，使用可取消的串行工作队列并核对会话代次，防止旧结果覆盖新输入。

正式资源保持现有格式契约，优先只读映射，不在扩展启动时解压、导入或训练模型。只加载首版需要的资源，不默认带入桌面 GPT2 重排。内存回收后必须能重建。具体内存预算以真机测量确定，不把网上流传的某个固定扩展内存上限当成通用保证。

首版只依赖扩展自身的资源与沙箱；本地学习应有大小限制与可恢复写入方案。主 App 与扩展共享设置或词库属于后续能力，需要结合 App Groups 和完全访问权限另行设计，不能让无完全访问时的基本输入失效。

拟新增目录（目前尚未创建可用工程）：

| 路径 | 职责 |
|---|---|
| `platform/ios/host/` | 安装引导与测试 App。 |
| `platform/ios/keyboard/` | 键盘控制器、按键和候选界面、桥接。 |
| `platform/ios/native/` | 移动端会话适配与静态核心构建入口。 |
| `platform/ios/resources/` | 公开演示资源与扩展配置。 |
| `tests/ios/` | 移动端操作、会话边界及资源失败回归。 |
| `tools/ios/` | 构建、检查及必要的源码交付工具。 |

引擎公共契约仍放在 `include/coral/`，领域实现仍放在 `modules/`；不复制整套核心到 iOS 目录。正式词库继续遵循仓库现有数据边界，不提交到公开源码。

## 5. 分阶段执行与验收

### M0：开发环境和首次安装

1. 核对 Mac 芯片、macOS、可用磁盘空间、iPhone iOS 版本。
2. 安装兼容的完整 Xcode，完成首次启动、许可确认和 iOS 平台组件安装。
3. 用户在 Xcode 登录自己的 Apple 账户，建立开发签名。密码和双重认证由用户在设备上输入。
4. Mac 开启仅允许指定账户的远程登录，完成 Windows 到 Mac 的认证和主机核对。
5. 在 Mac 建立独立项目目录，只同步客户端源码及明确需要的公开演示数据，不同步整个 `.release-work` 或私有资料。
6. iPhone 与 Mac 首次配对、确认信任，按提示开启开发者模式；首次安装建议使用数据线。
7. 验证最小 App 和扩展能安装、在设置中添加并切换，随后再建立无线调试。

退出条件：真实手机中可选择珊瑚测试键盘，且能够切换回系统键盘。记录 Xcode、SDK、macOS、iOS 与源码版本。

### M1：基础输入原型

先建立独立的会话测试入口，覆盖逐字输入、候选提交、部分转换、删除、翻页及过期候选拒绝；再接上界面和演示词库。

验收包括：输入 `nihao` 选择“你好”；输入长串后分段选词；有预编辑时删除拼音、无预编辑时删除宿主文字；候选翻页；英文大写；数字和标点；横竖屏；切换 App 或输入框后没有旧候选残留；资源缺失时有可理解的状态且仍能切换系统键盘。

退出条件：在测试 App 与备忘录中完成约定样例，离线且不开完全访问时通过。用户反馈触感、按键大小、候选可读性和误触问题。

### M2：完整引擎与日常试用

优先做两个技术试验：最小完整引擎能否在 Apple 工具链中构建；正式资源能否在扩展内稳定加载。根据结果逐步适配平台路径、锁、配置、日志和学习存储，再接入拼音查询、候选转换及组句。

用同一批人工构造样例对照桌面引擎，区分引擎质量差异和手机适配错误。记录首次打开、再次打开、每次候选更新的延迟分布，以及静置、长句、快速删除、连续切换后的内存峰值和恢复情况。

退出条件：指定词库版本下的基础功能回归通过，用户在常用 App 中完成至少两轮日常试用；没有已知的文本丢失、重复上屏、错位提交或反复崩溃问题。测量得到性能基线，再确定后续优化目标。

### M3：体验与发布准备

依据用户反馈补齐候选展开、符号效率、单手操作、无障碍及设置。扩展兼容测试覆盖更多输入框、系统版本与设备。整理隐私说明、许可与数据来源、测试记录、版本和分发流程；决定是否需要 TestFlight 和商店发布。上架前核对当时的 Apple 要求，审核结果不计作开发者可保证的交付。

## 6. 远程协作能做什么

同一局域网只提供网络条件，不等于已有设备控制权限。当前会话连接的是 Windows，尚不能直接在 Mac 上运行构建或操作 iPhone。

连接 Mac 后，可通过 SSH 进行文件同步、源码修改、编译、自动测试和日志检查。Xcode 与设备工具配置完成后，可尝试安装签名后的测试 App 和运行受支持的自动化测试。远程桌面或 Computer Use 是独立的接入方式，不能从 SSH 可用推断已有图形界面控制能力。

iPhone 的解锁、信任、开发者模式、系统权限和键盘启用等首次确认由用户完成。普通使用体验、实际输入反馈由用户验收；不把能够安装或跑测试等同于能够任意控制手机界面。

如希望从桌面 App 管理 Mac 上的项目，可另行按官方远程连接文档配置 SSH 项目或受支持的设备连接；下一次会话先验证实际可用能力，再选择最简路径。

## 7. 用户下一次开始前的准备

按顺序准备即可，无需先购买付费开发者会员。

1. 在 Mac 的“关于本机”记录芯片和 macOS 版本；在 iPhone 的“设置 → 通用 → 关于本机”记录 iOS 版本。
2. 从 Mac App Store 安装与 Mac 和手机系统兼容的完整 Xcode，打开一次，完成提示的组件安装。只有 Command Line Tools 不足以构建 iOS App。版本适配以 Apple 的 Xcode 支持表为准，不必为了本项目先装测试版系统。
3. 准备一根可以传数据的连接线，以及自己的 Apple 账户。签名登录和系统确认由你在设备上完成。
4. 下次准备连接时，再在“系统设置 → 通用 → 共享”开启“远程登录”，仅允许你的账户。把页面显示的 `ssh 用户名@地址` 发到会话，密码不发到聊天中。连接时再安排必要的本地认证步骤。
5. 保持 Mac 开机、联网，并留出首次配对与安装的时间。

免费 Personal Team 可用于个人设备开发测试，相关安装描述文件通常 7 天到期，届时需重新构建安装；正式分发与 TestFlight 再考虑 Developer Program。此项是账户使用条件，不是本轮已完成签名或安装的证据。

## 8. 验收分工与记录

开发侧负责实现、构建、行为回归、资源失败处理及性能数据；用户负责系统确认与真实打字验收。每轮提供明确的测试包或源码版本、已知限制和少量重点操作，不要求用户自行理解 iOS 工程内部结构。

建议每次问题反馈记录：源码/测试包版本、iOS 版本、所在 App、输入步骤、期望和实际结果、是否横屏、能否重复。反馈尽量使用人工样例，不需要提供私人聊天内容。

密码框等受保护输入和禁止第三方键盘的 App 可能使用系统键盘，这是平台边界，不能以“任意输入框都能使用第三方键盘”作为验收承诺。
