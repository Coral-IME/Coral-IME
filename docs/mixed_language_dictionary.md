# 中英文检索与统一语言模型

拼音音节表和英语检索索引继续独立。两种查询产生的词条共用主词典中的模型 ID 与一元权重，并进入同一个词格。英语不加入运行时拼音音节表。

## 词条身份和词频

- 中文 ID 保留原来的 `(word, fullPinyin)` 分配方式。
- 英文及 ASCII 技术词按忽略大小写的显示词建立身份，允许 `C++`、`CI/CD` 等拼写；查找键和显示词可以不同。
- 主词典已有的英文沿用最早的 ID，词频取其主词典各别名中的最大值。只有英语词典独有的词使用英语源词频；重复英语源条目取最大值。
- 新增英文 ID 紧接主词典 ID 范围，避免稀疏 ID 扩大 `languagemodel.coral` 的一元数组。
- `~en:` 开头的主词典键只保存英文模型词表，不用于拼音音节检索。英语仍由英语 trie 匹配。
- 英语一元词不使用中文低频阈值过滤，且具有自己的模型状态，即使暂时没有二元词对。已有语料中的中英词对会解析到同一套 ID；不会凭空生成关联概率。

## 切分、组句与候选

英语 trie 直接匹配原始输入区间，形成不参与中文音节拼接的英文边。原有中文 Top-K 切分保留；在缩图前额外保留经过每个可达英文区间的路径，保护其起止位置。英文和中文查询去重时区分查询类型，防止全大写输入被中文路径吞掉。

英语词典在混输中只接受查找键长度至少五个 ASCII 字符的词，四字符及以下的英语词典匹配不自动嵌入拼音组句，避免把 `zhuangb` 的末尾拆成 `zhuan + gb` 并显示“转GB”。该限制同时应用于英文区间建图、显式英文序列取词和中文查询未命中后的英文回退。完整输入的英文查询与补全不受此限制，例如单独输入 `gb` 仍可得到 `GB`；五字符词及 `Python` 等长词继续支持混输。该规则按查找键计算长度，显示词的大小写或标点不改变限制。主词典已有的拼音词条仍按拼音查询，不作为英语词典区间匹配处理。

中文搜索保留原有候选范围与预算。英文带来的额外中文切分只用于必须包含英文的路径；两个搜索共用词格、词频和语言模型，并按相同的长度及概率规则合并。混输搜索使用包含二元提升的代价下界，并在状态中区分是否已消费英文。

组句输出保留原来的最佳组句，并额外保留混输搜索的最佳整句，两者按统一评分排序并去重。中文组句评分较高时，完整英文匹配仍应作为候选出现；没有中英二元词对的数据包不保证混输首选。2026-10-14 修复了两种搜索合并后共用一个组句名额、导致低评分混输整句被丢弃的问题，该遗漏已存在于首次混输修复提交中。

额外保留限于多段组句，完整单个英文词继续使用已有候选及补全评分路径。额外候选带有内部标记，不参与原候选集的拼音纠错门控判断；该标记随候选移动，并在对象池重置时清除。

旧数据包中的英语 `id` 曾保存频率，装载后不再把它当作模型 ID。主词典能提供 ID 时复用该 ID；没有模型身份的英文按词权重评分，消费后清空此前中文上下文，避免跨过英文关联两个中文词。中文原有 OOV 行为保持不变。

完整英文参与词格竞争。补全先应用统一词权重，再排序取前十；未输入字符增加明确的补全惩罚。候选不再固定插入首位或第六位，也不依赖调试信息开关。英文身份查询表以不可变快照发布；模型完成装载和估值表构建后才对查询可见。

## 数据生成与安装

索引生成链：`tools/data/index_lexicon.py --english eng_lexicon.csv` 自动并入 `eng_lexicon.csv`，`index_bigram.py` 将英文词对映射到统一 ID。DLL 数据生成同时从该索引刷新 `mainlexicon.coral`，避免旧中文文本 trie 覆盖拼音索引。

直接生成链：

```text
coral_lexicon_builder --csv coral_lexicon.csv coral_languagemodel.csv output_dir eng_lexicon.csv
```

轻量安装包的压缩工具使用 `--english eng_lexicon.csv`，将模型英文词条一并编码进词典 bundle。安装期解包得到 `~en:` 模型词条后，`coral_lexicon_builder --csv` 自动恢复统一身份，不需要 Python 或额外英语源文件。压缩数据内部的字符串字典不等于运行时拼音音节表。

运行时可继续读取旧数据包；要覆盖全部英语词典并利用新增中英词对，应重新生成并成套部署 `mainlexicon.coral`、`languagemodel.coral` 和英语词典，并更新配置中的版本和校验值。

## 验证

`mixed_language_test` 覆盖双向中英词对、英文在句首/中间/句尾、短英文与中文竞争、全大写/驼峰拼写、显式分隔、补全排序、旧英语 ID 和未知英文上下文。

人工竞争样本额外覆盖缺少中英二元提升时，较高评分的中文组句保持首选，较低评分的混输整句在句首、中间和句尾均保留且不重复。

短英文回归覆盖二、三、四字符词在句首、中间、句尾和显式分隔后的过滤，显式英文与旧取词回退两条入口，以及五字符边界和独立短英文查询。低评分竞争夹具使用五字符词 `China`，符合当前混输长度规则。

`mixed_language_pipeline` 比对 Python 索引和直接 C++ 构建的 ID/权重，并验证轻量 bundle 解包后生成的两个模型文件与直接构建逐字节一致。

原提交在其私有数据环境中使用隔离用户目录对照了 1,000 条实际输入：旧包和重新生成的统一数据包均保持原首选；其中 943 条有中文目标，首选命中 735 条、前十命中 838 条，与修改前相同。这批样本不是完整准确率基准，也不代表新增中英语料的质量；这些结果不代表当前公开工程重新执行了该批评测。

原提交报告该批样本的输入耗时 P95 从约 0.29 ms 增至约 0.49 ms，增加来自英语匹配和额外的混输搜索。原提交的按键序列及词库导入/撤销回归也已通过。测试数据包和用户目录均隔离，未替换已安装输入法。
