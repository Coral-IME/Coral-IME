# 在线词库配置与请求生命周期

2026-10-14，第六批 E3b。维护者选择默认禁用，配置新服务后启用；词库算法与格式继续保留。

## 职责与当前接入

旧 `ui/celllexiconmanager.*` 迁入 `apps/settings_app/online_lexicon_coordinator.*`，采用 `coral::lexicon_catalog::OnlineLexiconCoordinator`。项目类型、方法、变量、成员和常量遵循现有开发规范；完整映射见 [迁移表](online_lexicon_catalog_migration.json)。服务地址及路由契约位于 `include/coral/lexicon_catalog/service_endpoint.h` 和 `modules/lexicon_catalog/`，由独立 `coral_lexicon_catalog` 静态目标提供。

核对当前主程序，旧管理器虽然编译，但没有外部检查/下载调用；旧注释描述的 2 分钟/6 小时自动定时器未接入，原 `startAutoCheckDownload` 本身为空。本批删除无使用方的空启动和定时器标记接口，不新增自动下载、定时器或 UI 入口。主程序仅引用新头，并在核心、消息窗口和日志停止之前调用 `stop`。服务配置使可调用管理器具备新服务地址，不意味着当前产品界面已经激活该功能。

## 默认门控和路由

`CORAL_LEXICON_SERVICE_BASE_URL` 默认为空，空值使 `LexiconService` 不可用，目录查询和下载定位 URL 均返回空。`check_now` 与 `on_auto_check_timer` 经共同门控返回，不创建 HTTP 请求或触碰词库目录；定位与响应处理也核对服务及本轮令牌。旧 `shurufa.coral.cn/api/v1/dict` 主机地址从该业务移除，没有旧地址回退。

非空配置限于最多 8192 字节的 ASCII `https://host[:port][/base]`：host 字符为字母、数字、点或连字符；port 为十进制 1..65535，可带前导零；base 只接受字母、数字、点、连字符、斜线、下划线和波浪号。拒绝凭据、query、fragment、空白、Unicode、IPv6 字面量、引号、反斜线及代码转义字符，去掉末尾斜线。此为配置字符规则，不代替完整 DNS/服务器有效性验证。运行期构造器与 CMake 配置均校验，非法非空值明确失败。

| 方法 | 固定路由（附加到新 base） |
|---|---|
| catalog_url | `/api/v1/dict?autoDownload=1` |
| location_url(id) | `/api/v1/dict/getDownloadUrl?Id=<十进制 id>`，id 为 1..INT32_MAX |

保留原路由和 JSON 字段形状，不将新地址拼接称为新词库格式。配置只影响本业务，不宣称设置、反馈、AI 等其他路径全部离线。返回的下载 URL 仍由旧运输接收，其协议/重定向/接收大小尚未按新更新运输标准改造。

## 对象与本轮请求

管理器的检查、停止和销毁在拥有它的 app 线程执行，不提供并发调用保护。管理器拥有目录、定位和下载三个请求。每次允许的新检查先结束旧请求，再创建本轮 `run_` 令牌。已有进行中请求/下载的跳过条件保留。工作线程回调捕获 weak token，过期时不投递；已经排入主线程的任务执行前再次检查令牌，不能利用静态 `instance()` 找到另一轮对象并处理旧应答。允许显式构造对象并传入 `LexiconService`，服务值归对象拥有。

`stop` 先使本轮令牌过期，再取消三个请求，销毁句柄以等待旧网络工作线程；析构调用同一路径。不能把原 `HttpRequest::stop()` 的设置取消位当作线程已结束。当前旧 `coralnet` 析构会 join，但 DNS/库调用仍可能延长等待，不保证严格停止时限。本批没有修改旧网络库、创建 detached 线程或声称真实联网取消已经验收。停止后的迟到任务不继续写词库；原请求的临时文件清理和完整事务仍待后续。

## 保留算法与未解决部分

保留 XOR key 与 `.kcell` 内容、`cell` 目录、`lexicon_record.json` 字段、CSV 与 combined 产物，以及列表解析、对账、串行队列、SHA256、编译和记录保存逻辑。XOR 是原有混淆方式，不是新增加密方案。22 个保留函数在逆向符号映射后逐 token 核对一致，控制流、操作符和字面量保留；服务门控、回调与对象生命周期改变单独分类，不能把整个管理器登记为独立重写。

保留实现仍有明确后续项：列表/记录接受不做完整严格校验，哈希读取和响应接收尚未有界，下载沿用旧 `DownloadTask`（其 setup 未设置 URL/公共选项），调用仍给出无限下载超时；record 先删除旧文件再 rename，写入/目录重建不是完整事务；现有校验与重建流程会删除指定旧词库文件。默认门控避免未配置时进入这些流程，不能据此声称配置服务后真实端到端下载已可用。词典算法保留决定不等于这些外围运输和文件事务已经完成。

## 验证

新增服务契约、实际 CMake 配置规则与管理器生命周期三项回归。运行期夹具覆盖独立人工路由、空服务、合法端口/id 和非法配置；CMake 实际脚本接受 4 个合法配置、拒绝 15 个非法配置。另一个构建树用 `https://new.example.test/catalog` 实际生成配置并编译/运行服务契约，无网络请求。

管理器夹具编译同一生产源码，只替换 HTTP、主线程队列、用户路径和编译动作：验证默认/显式空服务不请求或写词库，进行中不重复，停止/析构后工作回调与排队任务失效，旧轮不影响新轮，定位/下载阶段迟到回调也无写入，三个句柄被回收。人工三字节 `abc` 应答通过实际 CNG、XOR 文件与原重建流程，编译替身返回失败后不保存新 record。夹具仅写隔离目录，不启动正式词库编译或访问现有用户数据。

本批默认测试从 51 增至 54；配置更新服务时去掉默认禁用更新程序用例，变为 53。真实 HTTPS 服务、完整在线词库运输、严格停止时限及记录事务未验收。UI、TSF 和词典核心保持既有边界，执行状态见 [去重计划](code-separation.md)。
