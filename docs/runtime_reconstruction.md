# 模型重建与本地端口代次

第五批 B2b1 完成进程内关闭后重开。词典检索、评分、学习和文件编解码算法保留；本轮重写的是实例寿命与端口失效规则。

## 生命周期

内部解析器的既有 `instance()` 入口保留为过渡适配，实际对象改由可释放的唯一所有者持有。`stop_runtime()` 先标记不可用，析构解析器时等待加载任务、停止学习历史及候选规则工作，再释放模型映射、纠错器、候选缓存、middleware 和已创建的形码/符号实例。随后释放简繁转换器并停止日志工作。重复关闭不会为了关闭而新建解析器。

下一次初始化创建全新解析器，重新绑定用户配置文件和共享配置连接；简繁转换器重新绑定数据目录，首次转换才打开 OpenCC。正在运行时重复初始化在修改配置和日志前返回失败。启动异常执行关闭并返回失败；同步加载失败也会清理，之后可重试。同步加载偏好仍受既有 Windows 运行模式策略影响，异步启动成功仍不表示所有模型已加载成功。

异步启动后首次解析会等待整批词库加载完成；失败返回 false 并清空输出，不使用部分完成的模型。模型的显式加载、重试和完整解析共用加载锁，加载开始前撤销就绪并清候选缓存，只有任务完成并按既有资源规则成功后才发布就绪。普通模式不自动重新加载，启用 retryUntilSuccess 才在后续解析入口同步重试。该同步不替代所有者在关闭/重建前停止请求和释放借用引用的责任，不能跨实例并发使用全局解析 arena。

核心每次成功初始化分配新的进程内 64 位代次，失败不发布代次，耗尽后拒绝初始化。代次不落盘、不加入 CSW4、不代替宿主的协议代次。

## 所有权与失效

本地端口在构造时绑定当前核心代次。未初始化时构造的借用端口保持不可用；启动后应重新创建端口。核心关闭或代次改变后，该端口的查询、开会话和历史写入均不可用，旧会话不能复活。会话令牌继续进程内单调分配、不重复。

拥有初始化责任的端口仅在仍绑定当前核心时负责关闭。外部串行关闭并重开后，旧拥有者析构不会关闭新的核心。工厂及本地端口共用同一二进制内的锁；内部 `core_operations` 直接调用、设置存储的借用指针和模型视图仍要求调用方串行管理。关闭前必须停止请求并结束所有借用访问，不能跨重建保留解析器引用、词条视图或配置存储指针。

## 验证与边界

`runtime_restart` 在一个正常返回的进程内切换两套隔离的公开人工数据，第二套将“你好”候选改为“您好”，简繁结果由“中國”改为“中囯”，并使用不同 U 模式配置。源词表和实际查询的编译词表保持对应、记录宽度不变；这是测试夹具，不能作为生产词库生成方案。两套使用同一演示版本，切换后仍返回正确数据。

测试还覆盖重复初始化、启动前的借用端口、带旧会话的端口、过期拥有者析构、错误纠错模型校验后修复并重试，以及三轮异步关闭后同步重开。重复重开后检查进程句柄数没有持续累积；这不等同于全进程内存泄漏证明。

本轮 x64 Release/Debug 全量构建及默认回归各 35/35；Win32 静态核心、资源编译器和 TSF 构建通过。既有人工演示数据、登记第三方文件和只读对照文件未改动。

B2b2 已完成生产宿主跨进程归属和可中断管道，普通查询、空闲/未读连接下正常退出及直接重启已验证，见 [宿主生命周期](session_host_lifecycle.md)。剪贴板/UI 的所有后台资源尚未专项验收；此处不能声称它们全部支持重建，也不能将进程内代次当作跨进程隔离证据。既有单例适配和部分历史命名仍留给后续批次，见 [去重计划](code-separation.md)。
