# Windows 会话宿主的归属与关闭

第五批 B2b2 重写生产宿主的请求、会话和传输寿命。CSW4 的版本、72 字节信封及业务载荷不变；词典算法、模型和数据格式保留。原 AppContainer/Search 包的管道访问配置保留，底层词典仍由静态核心提供。

## 初始化责任

宿主通过 `make_initialized_session_port` 拥有核心初始化和关闭责任。启动锁在当前 Windows 会话内互斥，已有实例仍在运行时，第二个宿主正常返回；放弃的锁可重新获取。启动生成随机的非零宿主代次，并从该代次派生远程会话令牌的起点，在本实例内单调分配、不重复；内部核心令牌不暴露到管道。随机代次降低跨重启碰撞概率，不是永久全局唯一标识。

Windows 默认地址保持 `\\.\pipe\CoralPinyin.Session.v4.<会话编号>`，启动锁为 `Local\CoralPinyin.SessionHost.v4.<会话编号>`。新增停止事件 `Local\CoralPinyin.SessionHost.Stop.v4.<会话编号>`，访问由当前用户和 SYSTEM 的安全描述符控制。初始化失败或异常时，局部所有者负责回收对象和已启动工作。

测试使用 `CORAL_TEST_NAMESPACE`，管道、锁和停止事件统一追加 `_test_<标识>`，与模型和配置隔离配合。所有参与进程必须使用相同标识；只接受最多 64 个 ASCII 字母、数字、下划线或短横线，非法标识在打开对象或用户数据前拒绝。普通产品运行不需要此变量。

## 会话归属与数量

宿主从管道获取实际客户端进程编号，并要求它与宿主处于同一 Windows 会话。会话归属为实际进程 + `client_id`，保存可等待的进程句柄；请求不能自行提供进程身份。每次业务请求校验宿主代次、会话代次及归属。其他客户端、其他进程、错误代次或未知令牌返回 InvalidSession；非法控制字段或零客户端/请求标识返回 ProtocolError。不同客户端的关闭请求不会改变原会话。

每个进程/client_id 最多 64 个会话，宿主总共最多 256 个；达到上限返回 Unavailable。显式关闭释放容量，进程终止后的会话在请求调度或周期检查时回收；周期检查间隔 250ms，正在执行的模型操作可延迟检查。端口使用独立随机 client_id，析构时向最后已知宿主发送一次受截止值限制的租约释放请求，尝试清理该进程/client_id 的全部会话，包括回复丢失的打开请求；失败不会阻止析构，进程死亡回收仍是后备。单次传输预算最多 100ms，超时后的尽力取消通知另有最多 15ms 预算，系统取消完成仍须等待。客户端也应显式关闭不再使用的会话。传输连接超时只关闭连接，不删除仍有效的会话。

归属检查用于防止跨进程冒用客户端标识及错误会话路由，不能把同一进程内可自行构造的 client_id 当作恶意代码隔离机制。管道 ACL 和 Windows 进程边界仍负责访问控制。

Hello、Ping、OpenSession、FlushUserHistory 和 Cancel 为控制操作，不携带会话。B2b2 增加内部租约释放语义：CloseSession 的 session_id/session_generation 都为 0 时，释放当前管道实际进程/client_id 在该宿主代次的全部会话；不能释放其他进程或客户端。帧布局和操作编号不变，但应成套更新宿主/客户端，旧宿主没有此清理语义。公开 SessionPort.close_session(0) 仍为空操作，批量释放仅用于传输内部析构控制。历史刷新仍是全局操作。活动请求键包含实际进程、client_id 和 request_id；同时重复的请求拒绝，已完成请求不保留重放记录。取消只标记同一进程/client_id 的活动请求，不积累不存在的取消目标。已进入执行的学习操作可能有副作用，Timeout 不保证回滚或恰好执行一次；所有工作槽占满时，管道取消通知也可能无法及时到达。

## 可中断的传输

宿主固定八个工作槽，不按连接无限创建线程。ConnectNamedPipe、ReadFile 和 WriteFile 使用 OVERLAPPED 事件，与停止事件一起等待；连接等待可被停止事件打断，读取、写入和等待客户端关闭各最多等待 2 秒。停止到达后不再把已读取但尚未调度的请求送入核心。

每个连接只处理一个 CSW4 事务。写完回复后，宿主用可中断的读取等待客户端关闭，防止立即断开丢弃未读回复；停滞或不读取的客户端到时释放工作槽。移除同步 FlushFileBuffers，避免等待客户端读完时无法响应关闭。[Windows 异步管道说明](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-server-using-overlapped-i-o)。

停止或超时请求 CancelIoEx 后等待完成，随后才释放 OVERLAPPED、事件和缓冲。[CancelIoEx 的寿命约束](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex)。关闭顺序为停止传输、等待工作线程和在途模型操作结束、关闭会话、刷新学习历史，最后析构拥有者停止并销毁核心。无使用方的 `session_host_adapter` 外壳已删除。

这里的有限等待指管道阶段；已经开始的词典/学习操作仍等待自然结束，不能承诺任意模型死锁、文件系统故障或底层取消不完成时也具有硬性退出时限。剪贴板和 UI 后台工作仍需专项验证。

## 重连

客户端会话记录同时保存会话代次与原宿主代次。宿主变更时，关联检查使本次操作失败并清除握手缓存，后续调用重新握手、丢弃其他宿主代次的记录；旧令牌仍失效，需要重新开会话。PipeSessionClient 本身不重放业务操作；B2b2 当时保留 TSF 上层策略；第六批 A 已由独立 SessionBridge 重写桥接恢复与配置版本边界，见 [桥接契约](text_service_session_bridge.md)，完整 COM 焦点/特殊输入仍待专项。

宿主明确返回代次变更的 InvalidSession 时，客户端保留这一状态；成功回复的代次错配仍为 ProtocolError。首次握手与业务请求的时间预算仍分别生成，未改成一个总预算。

## 实际验证

新增 `session_host_process` 启动实际 `coral_engine_host.exe` 和独立探针进程，覆盖人工模型查询、简繁配置隔离、四个客户端进程并发查询、跨客户端与跨进程冒用、会话/宿主代次、截止值、异常帧、实例互斥、64/256 容量与死亡进程回收。

同一客户端经历宿主正常关闭并直接替换后，旧请求拒绝、重新握手成功，新会话可以查询。另让八个客户端保持连接不发送，或发送后不读取回复，宿主在这些句柄仍打开时正常返回；八个空闲连接也会自行超时并恢复可用。同一仍存活进程内六轮替换端口，每轮打开 64 个会话且不逐一关闭，析构后仍可使用全部 256 个槽。快速连接后立即断开也不会停止宿主。失败模型启动正常返回错误码 2，修复后宿主可重启并正常关闭。强制结束仅用于失败清理，发生时不计为成功。

当前 x64 Release/Debug 全量构建和默认回归各 36/36；Win32 核心、客户端、资源编译器和 TSF 构建通过。人工演示、词典源码、第三方及只读对照哈希保持不变。本轮未重新暂存安装包、安装、签名或发布。

本测试是正常桌面客户端与生产宿主的跨进程验证；完整 TSF 焦点/组合文本、Search/AppContainer 实际运行、特殊输入/剪贴板/UI 的端到端生命周期仍由第六批补充。既有窗口冒烟与协议夹具不能替代这些专项证据。当前进度见 [去重计划](code-separation.md)。
