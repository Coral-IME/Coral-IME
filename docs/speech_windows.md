# Windows 语音输入

## 开发期入口（2026-10-28）

`platform/windows/speech/speech_runtime.h` 的 `kSpeechFeatureEnabled = true` 恢复设置导航和语音宿主。以后改为 `false` 并重新构建即可再次统一屏蔽；既有用户开关无法绕过它。用户的“启用语音输入”仍默认关闭，不自动开启录音。

大窗和未经设计的点击录音入口暂时屏蔽：`kSpeechToolbarEnabled = false`，桌面工具栏保持五栏，旧 `kSpeechOpenMessage` 与 `open(false)` 不开始采集或展示界面。“检测麦克风”只使用底部小控件，不打开旧的大窗。

## 按住说话

1. 在“设置 → 语音输入”打开开关，保存自己的腾讯云 SecretId/SecretKey。
2. 按住已配置的快捷键开始录音。默认 **Ctrl + Win + Shift**，也可选择 Ctrl + Win + Space、Ctrl + Alt + Space、Ctrl + Shift + F8、Ctrl + Win。
3. 录音时在原窗口所在显示器工作区的底部中央显示 **56 × 56 DIP** 小话筒。控件不激活、不抢焦点，没有文字框、结束按钮或确认按钮。
4. 松开任一必要键立即停止采集，一次提交整段音频识别。识别期间原小控件显示忙碌点，不做流式转写，不自动重试云端请求。
5. 自动向原窗口当前仍有效的输入光标写入文字，成功后隐藏控件。不需要手动确认、复制或点击“输入文字”。
6. 没有可用光标、原窗口/焦点变化、修饰键迟迟未松开或系统拒绝注入时，全文自动存入剪贴板，并显示 **360 × 56 DIP** 轻提示，约 3.2 秒消失。

左右修饰键和不同按下顺序均支持，自动重复不会创建新任务；一段结束后须全部松键才能开始下一段。按住组合后又按其他键会取消本段，防止更长系统快捷键误上传；Esc 同样取消。监听只保存按键状态，不记录文字。Win 松开及 Space/F8 主键的重复/松开按需吞掉，避免开始菜单或空格泄漏。

原“按下发言”模式切换从设置页移除；所有快捷键统一为按住录音。旧 `speechPushToTalk = true` 仍按 Ctrl+Win 解释；选择新快捷键时清除此旧标记。旧配置访问接口继续兼容，不保留点击录音模式。

录音通过默认输入设备采集为 16 kHz、单声道、16 位 PCM，全部在内存保存。单段上限 60 秒，到达上限自动结束。麦克风检测最多 5 秒，仅提示有无声音，不上传、不写音频文件。

## 写入与失败处理

- 写入时复核原窗口、进程、线程、焦点控件和前台。使用系统 caret；自绘编辑器补充检查 UI Automation 活跃且可编辑的插入点。UIA 按[微软线程说明](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading)在无窗口的 MTA 工作线程调用，设置连接/事务超时，不改变界面线程 COM。密码和只读控件不自动注入。
- 不强行恢复或切换前台；UIA 查询返回后再次核对前台/焦点。使用确认时的当前光标，不保存编辑器内部偏移。
- 残留修饰键最多等 1.5 秒，再回退复制；剪贴板被占用时有限重试。复制仍失败会保留内存结果，显示可点击重试的轻提示，避免静默丢字。开始新一段或取消会清除此结果。
- 部分注入成功时不自动重放，复制全文并提示核对，避免重复输入。
- 空识别和失败只显示轻提示，不覆盖剪贴板。
- 关闭语音、删除/轮换凭据或更换快捷键会取消在途工作，迟到结果不得写入或复制。已发送到云端的处理与计费无法撤销。

凭据使用当前 Windows 用户 DPAPI 加密后保存于原有配置。共享设置只有开关、快捷键、就绪标记及版本，不含密钥。录音、密钥和识别正文不通过窗口消息传递或写入产品日志。主动上传及自动剪贴板行为同步到隐私政策和设置说明。

## 验证方法

- `coral_speech_shortcut_test`：人工按键夹具覆盖全部组合及顺序、任一必要键松开、重复、额外按键取消、左右键与完整松键后重启。
- `coral_speech_runtime_test <输出目录>`：隔离麦克风/识别后端和剪贴板；覆盖按住期间不识别、松键一次识别、快速松键、取消、停用、凭据轮换、切换快捷键、空结果、网络失败、剪贴板暂占与复制重试、提示自动隐藏，以及 96/120/144/192 DPI。
- `coral_speech_runtime_test <输出目录> interactive`：只向该测试创建的编辑框注入，检查自动写入、不抢焦点、只读和切换到第二个自有窗口后的复制回退。不触碰用户真实剪贴板。默认通过 `ImmDisableIME` 隔离测试线程，避免加载现用输入法及读写其用户数据。
- `coral_speech_runtime_test <输出目录> interactive-ime`：显式保留现用输入法的兼容性复现入口。本机该模式在销毁测试编辑框时触发系统 `textinputframework.dll` 空指针异常，转储显示加载了已安装的 `System32/coraltsf64.dll`；该问题未归因为语音模块，也未修改或替换现用安装，不能把隔离测试通过称为现用输入法兼容验收通过。
- `coral_speech_runtime_test <输出目录> microphone`：单独检查设备；没有设备须如实记录，不能记作真实采集通过。
- `python tools/checks/speech_sample.py --probe <coral_speech_probe.exe> --manifest <manifest.jsonl> --output <新的结果.json> --count 15`：选最短/最长及固定种子随机 13 条，仅测试 15 条，不跑全集。凭据通过进程环境提供；结果写到忽略的构建目录，禁止提交语料或实际转写。字符错误率忽略空白、标点及全半角差异，不把中文数字和阿拉伯数字视为相同。

跨平台模块、音频约束、HTTPS 协议及凭据环境见 [语音基础模块](speech_input.md)。本轮实际结果见构建目录 `speech-hold-validation/` 及测试日志；编译、隔离交互、真实麦克风和安装验收分别记录。
