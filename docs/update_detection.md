# 更新检测与下载安装

当前实现说明，更新于 2026-10-21。源码默认程序版本为 **1.0.0.3**；构建覆盖及打包一致性见 [构建说明](build.md#程序版本)。已安装的旧测试包不因服务器或文档变更获得新代码。

## 服务和版本

`CORAL_ENABLE_UPDATES` 默认 ON，`CORAL_UPDATE_SERVICE_BASE_URL` 默认 `https://coralime.cn`；启用时旧空缓存会迁移到官网，自定义 HTTPS 地址保留。离线构建显式设置 `CORAL_ENABLE_UPDATES=OFF`，空地址不作为禁用方式。主程序和下载程序共用有效配置。

检查请求为 `<base>/api/v1/version/latest`。本机版本先读取运行程序相邻 `config/coralpinyinConfig.ini` 的 app/Version，缺失或无效时回退到程序 VERSIONINFO；不读取注册表或用户可变偏好。按四段数字比较，只有服务端更高版本才提示更新，同版本手动检查显示“当前已是最新版本”。

## 检查时机和生命周期

- “关于”页提供手动检查和默认开启的“自动检查更新”，开关持久化为 `isAutoCheck`。
- 用户设置进程启动约 60 秒后开始调度，每分钟评估一次；距离上次已发起检查不足 24 小时不自动请求。手动检查不受自动开关和间隔限制，但也更新检查时间；失败计入间隔，时钟回拨允许重新检查。
- 手动操作可将进行中的自动检查提升为手动结果，不并发发起检查。同一版本已展示后不再自动弹窗，手动仍可展示；关闭自动开关抑制在途自动结果。
- 检查线程由协调器持有、取消并等待。退出时使生命周期令牌失效，拒绝迟到任务；检查失败不冒充最新版本。

## 元数据和用户动作

生产接口使用 `schema_version=2`，例如以下人工文件的元数据（不是实际发行信息）：

```json
{"schema_version":2,"data":{"id":7,"version":"1.0.0.4","fileSize":3,"fileSha256":"ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad","description":"人工版本"}}
```

输入限 64KiB，完整验证 UTF-8、唯一字段、四段版本、发布 ID、包大小、SHA256 和说明。失败不保留部分结果。窗口显示只读更新说明；用户点击“立即更新”才启动私有 CUP1 下载进程，按已显示发布 ID 请求 `<base>/api/v1/version/getDownloadUrl?Id=<id>`，不重新选择 latest。

旧 `schema_version=1` 通知仍兼容，要求固定格式的 HTTPS GitHub 版本发布页；该分支仅打开发布页，不启动包下载。它不改变版本 2 的直接下载安装流程，也不作为官网更新服务的默认来源。

下载进程检查 HTTPS、接收限额、实际长度和摘要，并以同一已校验句柄、不覆盖现有目标的方式发布缓存。窗口显示进度，支持取消、失败重试和防止重复执行。关闭窗口取消并等待自己拥有的下载；缓存不会因取消或关闭自动检查而全部删除。安装前重新校验，成功后调用系统启动安装程序，UAC 仍由用户确认；启动失败可重试，启动成功后禁止重复启动。

## 服务端、验证和限制

更新服务端是同级独立 `server-side` 仓库，接入见 [独立服务端仓库](build.md#独立服务端仓库)。只读 Python 服务配合 HTTPS 反向代理提供 latest 和按 ID 下载地址，不要求客户端用户账户或输入内容。生产日志与地域见 [隐私政策](legal/隐私政策.md)。

默认回归使用人工 JSON/文件、隔离子进程及本机服务；真实 HTTPS 探针 `coral_update_online_probe` 需显式运行，仅下载校验，不执行安装包。客户端测试数与服务端项分别见 [维护与验证](maintenance.md)，具体构建结果以 [基线报告](build-baseline.md)和 [维护记录](code-separation.md)为准。

文件接受与取消详见 [安装包接受](update_package_acceptance.md)和 [私有更新通信](update_private_channel.md)。HTTPS 与 SHA256 不等于发布者签名认证，校验返回到 Shell 启动之间仍有路径替换间隙；真实安装、升级后重启和签名信任须独立验收。
