# candidate_policy

用户手动维护的候选策略，负责“固定首位/取消固定”和“禁用候选”。

它与自动学习历史分开：

- 来源是用户显式操作，不随上屏自动增删；
- 在完整解析结果形成后按 `(简繁体, 完整输入拼音, 候选文本)` 应用；
- 不参与历史频率、时间衰减和 100,000 条历史容量淘汰；
- 使用独立文件 `user_candidate_policy.coral2`、generation、CRC、备份和原子替换；
- `Snapshot` 为查询提供按输入拼音的不可变有序视图；
- `Manager` 负责手动 mutation、跨进程刷新和后台 checkpoint；
- `Storage` 可从旧 `user_history.coral2` 的策略分区或旧简体/繁体候选规则文件迁移。

同一语言、同一输入拼音最多保留一个 `pinned-first` 规则。禁用规则只影响其
对应输入拼音，不再像旧实现一样按文本全局屏蔽同名候选。

业务接口统一使用 `coral::LanguageVariant` 表示简繁，使用 `CandidateAction` 表示
固定首位、取消固定或禁用；不再使用四类词典枚举或特殊位置数字表示操作。
常用语作为非固定的 Promote 规则排在普通候选之前，固定候选优先于常用语。
运行时 Rule 不再保存指定位置；V1 文件中的位置槽仅在 Codec 中兼容读写。
旧文件中的正位置统一按首位规则读取，再次写入时规范为 1；禁用规范为 0。

禁用仅允许实际上屏文本中的多字符词语。单字仍可固定到首位，但不显示删除
入口，控制器和引擎也会拒绝禁用；旧单字禁用规则在读取快照时忽略。
字符数按 UTF-8 Unicode 字符计算，扩展汉字及其变体选择符不会被误判成词语。
